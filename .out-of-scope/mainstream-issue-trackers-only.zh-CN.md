# Issue 追踪器集成仅限于主流工具

`setup-matt-pocock-skills` 仅为主流 Issue 追踪器提供一流支持。添加对小众、新型或单一供应商实验性追踪器的支持请求在范围之外。

## 为什么这在范围之外

每个 Issue 追踪器后端都会将 CLI 形状硬编码到技能中（命令、标志、输出解析）。每个新后端都是永久维护面——它必须随着工具 CLI 的发展保持工作，并且必须继续针对 `/to-prd`、`/to-issues`、`/triage` 和相关功能进行测试。只有对有意义的用户 fraction 实际拥有的追踪器，这种成本才值得付出。

"主流"是判断，不是数字门槛：

- GitHub、GitLab 和 Backlog.md 是我们会考虑的主流类型——广泛知晓、广泛使用、早已超越实验阶段。
- 拥有几百 GitHub 星的全新 Agent 聚焦工具不是，无论设计多么有趣。

星标、年龄和下载计数在做出判断时是有用信号，但都不是规则。规则是：典型工程师会认识这个工具并可能为他们的团队选择它吗？

非主流追踪器已经存在逃生舱：

- 用于轻量级 in-repo 跟踪的 `local markdown`。
- 用于想要自己连接某物的用户的 `other/custom`。

两者都不需要核心技能了解特定工具。
