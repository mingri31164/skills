# 逻辑原型

一个tiny交互式终端应用，让用户手动驱动状态模型。当问题是关于**业务逻辑、状态转换或数据形状**时使用——那种在纸上看起来合理但只有在手工推动它通过真实案例时才感觉不对的东西。

## 这是正确形状的时候

- "我不确定这个状态机是否处理了 X 然后 Y 的边缘情况。"
- "这个数据模型实际上让我表示...的情况吗？"
- "我想在实际编写之前感受 API 应该是什么样子。"
- 用户想要**按键并观察状态改变**的任何时候。

如果问题是"这应该是什么样子"——错误的分支。使用 [UI.md](UI.md)。

## 流程

### 1. 陈述问题

在写代码之前，写下你正在原型化的什么状态模型和问题。一段，在原型的 README 或文件顶部的注释中。回答错误问题的逻辑原型是纯粹浪费——使问题明确，以便以后可以检查，无论是用户现在观看还是 AFK 返回。

### 2. 选择语言

使用主机项目使用的任何语言。如果项目没有明显的运行时（例如一个文档仓库），问。

匹配项目现有的工具约定——不要仅为原型添加新的包管理器或运行时。

### 3. 在可移植模块中隔离逻辑

将实际逻辑——回答问题的部分——放在一个小、纯接口后面，可以提取并放入真实代码库中。周围的 TUI 是可丢弃的；逻辑模块不应该是。

正确的形状取决于问题：

- **纯 reducer** — `(state, action) => state`。适合动作是离散事件且状态是单一值时。
- **状态机** — 显式状态和转换。适合"哪些动作在当前甚至是合法的"是问题的一部分时。
- **纯函数小集合**处理普通数据类型。适合没有隐式当前状态——只是转换时。
- **类或模块具有清晰的方法表面**当逻辑真正拥有持续的内部状态时。

选择最能回答被问问题的形状，_而不是_最容易连接到 TUI 的形状。保持纯：无 I/O，无终端代码，无 `console.log` 用于控制流。TUI 导入它并调用它；没有东西流向另一个方向。

这就是使原型在其自己的生命周期之外有用的原因。当问题被回答时，验证的 reducer / 机器 / 函数集可以提升到真实模块——TUI shell 被删除。

### 4. 构建最小的暴露状态的 TUI

作为**轻量级 TUI** 构建——每次 tick，清屏（`console.clear()` / `print("\033[2J\033[H")` / 等效）并重新渲染整个帧。用户应该始终看到一个稳定视图，而不是不断增长的回卷。

每个帧有两部分，按此顺序：

1. **当前状态**，美观打印和 diff 友好（每行一个字段，或格式化的 JSON）。字段名或节标题使用**粗体**，不太重要的上下文（时间戳、ID、派生值）使用**暗淡**。原生 ANSI 转义码可以——`\x1b[1m` 粗体，`\x1b[2m` 暗淡，`\x1b[0m` 重置。不需要拉取样式库，除非项目已有。
2. **键盘快捷键**，列在底部：`[a] add user  [d] delete user  [t] tick clock  [q] quit`。键粗体，描述暗淡，反之亦然——什么读起来清晰就好。

行为：

1. **初始化状态** — 单一内存对象/结构。启动时渲染第一帧。
2. **每次读一个按键（或一行），分派到处理程序变更状态。
3. **每次操作后重新渲染**完整帧——不要追加，替换。
4. **循环直到退出。**

整个帧应该适合一个屏幕。

### 5. 使其一条命令可运行

添加到项目的现有任务运行器（`package.json` 脚本、`Makefile`、`justfile`、`pyproject.toml`）。用户应该运行 `pnpm run <prototype-name>` 或等效——永远不需要记住路径。

如果主机项目没有任务运行器，只需在原型 README 顶部放置命令。

### 6. 交接

给用户运行命令。他们会自己驱动；当他们说"等等，那不应该可能"或"呃，我以为 X 会不同"时，这些是_想法_中的 bug，这是全部目的。如果他们想要添加新操作，添加它们。原型演化。

### 7. 捕获答案

当原型完成其工作后，问题的答案是唯一值得保留的。如果用户在，问他们它教了他们什么。如果不在，在原型旁边留下 `NOTES.md`，以便在原型被删除之前（或者如果你观看了会话，由你）可以填写答案。

## 反模式

- **不要添加测试。** 需要测试的原型不再是原型。
- **不要将其连接到真实数据库。** 除非问题明确涉及持久化，否则使用内存存储。
- **不要泛化。** 不要"如果我们以后想支持 X"。原型回答一个问题。
- **不要将逻辑和 TUI 混在一起。** 如果 reducer / 状态机引用 `console.log`、提示或终端转义码，它就不再可移植。将 TUI 作为纯模块上的薄 shell。
- **不要将 TUI shell 投入生产。** shell 优化为从终端手动驱动。后面值得保留的是逻辑模块。
